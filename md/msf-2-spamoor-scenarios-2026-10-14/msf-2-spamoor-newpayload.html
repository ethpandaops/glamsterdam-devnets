Evidence and limits

The full-run line chart uses Xatu execution_engine_new_payload, ENGINE_SOURCE_SNOOPER, with duplicate records removed by block hash, request timestamp, node, client version, response, duration and gas used. Repeated real requests remain. Six nodes per execution client are included; builders, bootnodes and observer nodes are excluded. Five-minute summaries are split across disjoint 12-hour queries, so boundary bins are not combined from incompatible percentiles.

The independent block comparison computes new exact quantiles from individual RPC calls; it does not average the timeline's p95 values. RPC latency includes implementation behavior and can include cached responses. Erigon commonly responds SYNCING before execution finishes, so its quick RPC returns do not establish faster execution. Changes in client versions and gas use are visible in hover details.

Scenario IDs were found in Spamoor scheduler and wallet metadata. The inspected scenarios and sampled transactions did not establish a universal ID field in transaction calldata, value or fees. Unknown or conflicting address matches remain unknown. A pause does not remove queued transactions; scheduler history alone cannot identify what was mined. The run history may also span daemon restarts or unsuccessful starts. #111's configuration changed despite its persistent “existing slots” display name.
